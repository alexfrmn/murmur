# Первый запуск на чистой машине Windows — по шагам

Сценарий: человек получил ссылку. У него Windows, нет ни Node, ни файлов, ни
настроенного демона. Инженером он быть не обязан. Финиш — в трее цветной значок, и его
первое сообщение дошло до второго участника.

Три колонки. **Обязан увидеть** — то, что должно подтверждать шаг, чтобы человек знал,
что он не сломался. **Видит сегодня** — то, что происходит на самом деле; «ничего»
написано там, где ничего, и это список дыр, а не фигура речи.

Составлено 19.09.2026 по состоянию `main` на `9b345da` и по проходу на живой машине
Windows 10 Pro 19045. Где не проверял руками — сказано прямо.

---

## Этап 0. Человек получил ссылку

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| открывает ссылку | что это, кому и зачем; один путь входа для его системы | страницу репозитория: README на английском, первым содержательным разделом — список новостей версий v2.9…v2.3 |
| ищет, с чего начать | одну кнопку или одну команду | раздел `Install` с установкой через npm, над которым стоит предупреждение, что в npm лежит код версии 2.6 и публикация заморожена |

**Дыра 0.1.** Первый содержательный раздел README — история версий. Человеку, который
пришёл поставить продукт, она не отвечает ни на один из его вопросов.

**Дыра 0.2.** Раздел `Install` предлагает путь, который сам же объявляет нерабочим.
Человек, читающий сверху вниз и пропускающий цитату-предупреждение, поставит не то.
Решение лаборатории — npm не предлагать вовсе, пока публикация заморожена.

## Этап 1. Node

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| узнаёт, что нужен Node | требование версии до того, как что-то качать | «Node.js 22+» в разделе `Prerequisites`, ниже по странице, после раздела `The Problem` |
| ставит Node | подтверждение, что версия подходит | ничего: проверки нет, несоответствие выяснится позже падением на `node:sqlite` |

**Дыра 1.1.** Требование версии стоит после того места, где человек уже мог начать
ставить. Оно обязано быть до первой команды.

**Дыра 1.2.** Никто не проверяет версию Node за человека. `node:sqlite` появился в
22.5, и на 20.x всё выглядит установленным до первого запуска демона.

## Этап 2. Брокер

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| читает `Prerequisites` | адрес брокера лаборатории и как получить к нему доступ | команду `docker run … nats:2.10-alpine`, то есть предложение поднять свой брокер |
| пытается выполнить | работающий брокер | на чистой Windows Docker нет; проверено на этой машине — `docker` в PATH отсутствует |

**Дыра 2.1.** Сценарий «новый участник лаборатории» и сценарий «разработчик поднимает
свой стенд» в README не разведены. Участнику лаборатории свой брокер не нужен, ему
нужны адрес и токен. Сейчас он упрётся в Docker Desktop, которого у него нет, и это
самый вероятный момент, когда он уйдёт.

## Этап 3. Файлы

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| выполняет `git clone … && cd murmur` | склонированный каталог | это работает, если установлен git; требования git в `Prerequisites` нет |
| выполняет `npm install && npm run build` | сборку без ошибок | не проверял на чистой машине; на этой машине репозиторий уже собран |

**Дыра 3.1.** `git` не назван в требованиях, хотя первая же команда без него не
работает. На Windows он не предустановлен.

**Дыра 3.2.** `&&` между командами — синтаксис bash. В PowerShell 5.1, который стоит по
умолчанию на Windows 10, оператора `&&` нет: строка не выполнится и выдаст ошибку
разбора.

## Этап 4. Личность агента

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| выполняет команду из шага 1 README | созданный конфиг и своё имя агента | **ошибку разбора команды** |

Команда из README:

```bash
AGENT_ID=alice NATS_URL=nats://your-server:4222 NATS_TOKEN=YOUR_SECRET \
  node scripts/agent-config-init.mjs
```

Проверено на этой машине дословно:

```
The term 'AGENT_ID=alice' is not recognized as the name of a cmdlet, function,
script file, or operable program.
```

**Дыра 4.1, самая дорогая на всём пути.** Префикс переменных среды перед командой —
синтаксис bash. В PowerShell его нет вовсе. README обещает «Connect two agents in 3
commands. No JSON editing», и на Windows **ни одна из трёх команд не выполняется в том
виде, в каком написана**. Человек на этом месте либо знает, что переменные в PowerShell
задаются через `$env:AGENT_ID = 'alice'`, либо уходит. Ничто на странице ему об этом не
говорит.

**Дыра 4.2.** Обратный слеш для переноса строки — тоже bash. В PowerShell перенос
делается обратной кавычкой.

## Этап 5. Пара со вторым участником

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| выполняет `murmur-invite.mjs` | блоб приглашения и внятное «передай его второму любым каналом» | блоб печатается; это в README сказано |
| передаёт блоб, получает ответный | понимание, что и куда он передаёт и что в блобе нет секрета, который нельзя показывать | ничего: про содержимое блоба не сказано |
| выполняет `murmur-add-peer.mjs` | подтверждение, что пара установлена с обеих сторон | сообщение об успехе локальной операции |

**Дыра 5.1.** Человеку предлагают переслать блоб «любым каналом», не сказав, что в нём.
Он не может оценить, можно ли кинуть его в общий чат. Это вопрос «что это значит?» из
семи вопросов, и ответа на него нет.

**Дыра 5.2.** Подтверждение локальное. Факт, что пара установлена с обеих сторон,
ничем не проверяется — ровно тот случай, из-за которого в схеме статуса признак
парности сделан обнуляемым: локальные ключи не доказывают пару.

## Этап 6. Демон

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| выполняет `node scripts/murmur-daemon.mjs` | что демон запущен и будет жить дальше | строки журнала в окне терминала |
| закрывает окно терминала | предупреждение, что демон при этом умрёт | **ничего**: демон умирает молча вместе с окном |
| перезагружает компьютер | что демон поднялся сам | **ничего**: не поднимается |

**Дыра 6.1, вторая по дороговизне.** README оставляет демон в окне терминала и ничего
не говорит о том, что будет, когда окно закроют. Человек закроет — обмен встанет — и он
узнает об этом не сразу, а когда кто-то не дождётся от него ответа.

**Дыра 6.2.** Автозапуска нет. Служба Windows для этого сделана и лежит в PR #155, но
на `main` её ещё нет.

## Этап 8. Первое сообщение

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| подключает MCP: `claude mcp add murmur -- node /path/to/…` | подключённый сервер | путь в примере записан через прямые слеши и без кавычек; на Windows путь содержит обратные слеши, а `C:\Program Files\…` ещё и пробел |
| отправляет `murmur_send` | подтверждение доставки, которому можно верить | подтверждение приходит; сегодня в лаборатории поймали случай, когда подтверждали доставку зависшие процессы, ничего не сохраняя |

**Дыра 8.1.** Пример команды не переносится на Windows дословно. Пробел в пути без
кавычек разорвёт аргумент.

## Этап 9. Ответ агента

| действие | обязан увидеть | видит сегодня |
|---|---|---|
| ждёт, что его агент ответит на входящее | что агент разбужен входящим | **ничего**, пока человек руками не пропишет хук в `.claude/settings.json` |
| ищет, как это сделать | шаг в пути установки | раздел в `docs/wake-native.md`, на который из пути установки нет ссылки |

**Дыра 9.1.** Пробуждение агента — не дополнительная возможность, а условие, при
котором продукт делает то, что обещает. Сейчас это отдельный документ, о существовании
которого человек узнаёт, только если сам пойдёт искать, почему его агент молчит.

**Дыра 9.2.** На Windows работает только node-порт хука. Шелловый `wake-drain-claude.sh`
требует `sh`, которого на чистой Windows нет: хук вернёт пустоту, выйдет с нулём, и
пробуждение будет молча не работать. Это описано в `docs/wake-native.md` и не описано
нигде на пути человека.

## Итог: сколько раз человек остаётся без ответа

Шагов, на которых сегодня он не видит **ничего**: семь — закрытие терминала, ребут,
значок, doctor, status, пробуждение агента и предупреждение про `sh`.

Шагов, на которых написанное **не работает дословно на Windows**: четыре — `&&`,
префикс переменных среды, обратный слеш переноса, путь в примере MCP.

Шагов, на которых он **упрётся в то, чего у него нет**: два — Docker и git.

Ни один из них не является ошибкой человека. Каждый — место, где вещь не сказала, что
от него требуется.

## Что из этого закрывает одна команда установки

Этапы 1–4 и 6–7 целиком: проверка Node и git, запись конфига без ручного ввода
переменных, установка службы, регистрация значка на вход в систему, проверка, что всё
поднялось. Остаются человеческими этап 5 (обмен блобами — там нужен второй человек) и
этап 8 (первое сообщение).

Сценарий с командой установки описан в `INSTALL-COMMAND.md`, места, где мне самому
приходилось догадываться, — в `GUESSWORK.md`.
