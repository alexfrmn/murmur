# Одна команда установки — `Install-Murmur.ps1`

Делает то, что сегодня человек делает руками по `FIRST-RUN.md`: проверяет Node и git,
записывает личность агента, ставит службу, регистрирует значок на вход в систему и
проверяет, что всё это работает.

```powershell
.\Install-Murmur.ps1 -AgentId misha -NatsUrl nats://nats.example.org:4222 -NatsToken '<токен>'
```

## Правило, ради которого она написана

**Команда, вернувшая ноль, означает работающую систему.** Не «я сделала вызовы» —
«я проверила результат».

Это прямо из сегодняшнего: установка службы вернула ноль при неработающей службе,
потому что считала успехом создание записи в диспетчере. Следующая причина отказа была
бы другой, а форма отказа — той же: три команды подряд возвращают ноль и молчат.

Поэтому здесь каждый шаг заканчивается проверкой результата, а не факта вызова:

| шаг | что проверяется, а не предполагается |
|---|---|
| права | членство в группе администраторов до первого изменения в системе |
| Node | версия не ниже 22.5, потому что демон хранит сообщения через `node:sqlite` |
| git | наличие в PATH: первая же команда пути установки без него не работает |
| файлы | существование точки входа демона и собранного адаптера службы |
| конфиг | файл появился после запуска и в нём записан ожидаемый агент |
| служба | адаптер сам ждёт устойчивого `Running` и шести секунд жизни демона |
| значок | процесс жив через три секунды после запуска |
| итог | `status --json` отдаёт `running` уже после всей установки |

Шаг, который не удалось подтвердить, останавливает установку, называет причину и
говорит, что делать. Установка службы при неподтверждении откатывается сама — это
поведение адаптера, а не скрипта.

## Права спрашиваются один раз и объясняются

Единственное, ради чего нужен администратор, — регистрация службы в диспетчере. Каталог
данных, конфиг и автозапуск значка живут в профиле пользователя. Если окно запущено без
прав, скрипт говорит об этом до того, как что-либо изменит, и объясняет причину:
служба — операция уровня системы.

## Защита от второй сущности на одном хранилище

Перед установкой проверяются и служба с тем же именем, и **задача Планировщика** с тем
же именем. Сегодняшний демон на машинах участников живёт именно задачей, и установка
службы рядом дала бы два демона на одном хранилище. Скрипт в этом случае
останавливается и говорит, как снять задачу.

Проверено вживую на машине, где такая задача работает: установка дошла до шага 6,
отказалась, ничего не изменила и вернула 1.

## Грабля, найденная этим же скриптом

Файл `.ps1` в UTF-8 **без BOM** PowerShell 5.1 читает кодовой страницей ANSI. Русский
текст внутри превращается в мусор, и скрипт не запускается вовсе — падает разбором на
первой же строке с кириллицей:

```
Unexpected token 'РђР›РћРЎР¬:' in expression or statement.
```

Человек видит ошибку синтаксиса в файле, который синтаксически верен. Поэтому скрипт
сохранён с BOM, и это требование к любому `.ps1` с кириллицей в этом проекте.

Это третий случай за день одной формы: UTF-8 без метки, прочитанный ANSI. Первый —
логи через `Get-Content`, второй — буфер обмена через `clip.exe`, третий — сам скрипт.

## Чего команда не делает

- **Не обменивается приглашениями.** Там нужен второй человек, и это остаётся ручным
  шагом; команда печатает, какие именно три команды выполнить дальше.
- **Не ставит Node и git.** Только проверяет и говорит, откуда взять.
- **Не поднимает брокер.** Участник лаборатории получает адрес и токен, свой брокер ему
  не нужен.
- **Не правит `.claude/settings.json`** и не настраивает пробуждение агента. Это
  отдельный шаг, и пока он не автоматизирован, агент на входящие отвечать не начнёт.
  Дыра 9.1 в `FIRST-RUN.md` остаётся открытой.

## Приёмка

| проверка | итог |
|---|---|
| запуск без прав администратора | отказ с объяснением до любых изменений |
| Node ниже 22.5 | отказ с названной причиной (проверено чтением ветки, не подменой версии) |
| отсутствует `murmur-daemon.mjs` | отказ с указанием `-RepoRoot` |
| существующая задача Планировщика | отказ, ничего не изменено, код 1 — проверено вживую |
| шаги 1–5 на живой машине | пройдены, вывод по шагам, конфиг не тронут |

**Не проверено:** полная установка на чистой машине от начала до конца. На этой машине
демон уже работает задачей Планировщика, и запускать вторую сущность на том же
хранилище нельзя. Нужна чистая машина либо снятая задача — и то, и другое решает
владелец машины, а не я.
