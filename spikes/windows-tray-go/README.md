# Значок Murmur для Windows — спайк

«Пригласить коллегу» создаёт Приглашение общим CLI, сохраняет резервный файл в
`invites` выбранной Личности и копирует строку в буфер. Если Личности ещё нет,
открывается форма имени компьютера, адреса Сервера и необязательного ключа.
После подтверждения выполняются `init`, `service install`, `service start`, `invite`.
Установка и запуск Службы могут запросить UAC; отмена останавливает последовательность.
Ключ передаётся только через временный файл с DACL текущего пользователя и удаляется
сразу после `init`, включая ошибку. Ошибки показывают кнопку диагностики; в ней
сохраняются шаг и безопасный код. При частичном успехе созданная Личность сохраняется.
Если Служба использует приватный адрес, отдельное поле позволяет указать публичный
адрес для Приглашения: повторяется только `invite --broker`, без изменения Службы.

Трей-значок с логотипом Murmur: состояние видно цветом и подсказкой, детали в меню. Данные берутся только из
`murmur status --json` и `murmur doctor --json`, в SQLite значок не лезет.

## Сборка и запуск

```
go build -ldflags "-H windowsgui -s -w" -o murmur-tray.exe .
murmur-tray.exe
```

Для рабочего запуска нужны внешний Node.js 22.13.0+ и собранный CLI runtime.
Откройте `murmur-tray.exe`: без Личности появится окно с тремя кнопками —
«У меня есть приглашение», «Пригласить коллегу», «Я уже пользовался Murmur».
Язык можно выбрать в этом окне. Повторный запуск без Личности снова открывает окно.
[Лаунчер комплекта](../../apps/windows-tray/packaging/README-Windows.md) также позволяет
явно выбрать существующую Личность. Лаунчер проверяет CLI и передаёт значку
абсолютные пути Node, entry point, профиля и необязательное имя службы.

Для отладки значок может читать сохранённые ответы CLI:

```
set MURMUR_STATUS_FILE=C:\murmur-debug\status.json
set MURMUR_DOCTOR_FILE=C:\murmur-debug\doctor.json
murmur-tray.exe
```

Прямая привязка: `MURMUR_BIN` — абсолютный путь к Node, `MURMUR_CLI` — к
`packages/setup/bin/murmur.mjs`, `MURMUR_PROFILE` — к выбранному профилю,
`MURMUR_SERVICE_NAME` — необязательное имя службы. Поиск CLI через PATH не выполняется.
`MURMUR_STATUS_FILE` и `MURMUR_DOCTOR_FILE` — отладочный файловый источник, доступный
только без выбранного профиля; действия для него выключены. В рабочем режиме ошибка
CLI не заменяется снимком с диска.

При первом запуске язык выбирается по языку Windows (русский или английский). Язык можно
переключить через **Language → English / Russian (Русский)** или передать явно:

```powershell
.\Open-Murmur.ps1 -DataDir C:\Murmur\profile -Language ru
```

Выбор сохраняется в `%LOCALAPPDATA%\Murmur\tray-preferences.json` и применяется при
следующем запуске. Значок принимает только `en` и `ru`; переменные окружения с языком
не читаются. Каталоги `locales/en.json` и `locales/ru.json` встраиваются в EXE при
сборке, а тест требует полного совпадения ключей и параметров форматирования.

Сохранённый ответ должен содержать действительное время измерения: устаревший
снимок будет серым. Тестовые образцы находятся в
[`../../contracts/setup/v1/fixtures`](../../contracts/setup/v1/fixtures); их
политику `$stamp` применяет тестовый прогон. Это не готовые живые снимки для значка.

`murmur-tray.exe --dump-icons <dir>` выкладывает пять состояний значка файлами `.ico`
и `.png` — иконки собираются кодом, и это способ посмотреть на них в ревью.

## Общий знак и второй вход

Геометрия и цвета берутся только из
[`contracts/visual/murmur-mark.svg`](../../contracts/visual/murmur-mark.svg).
`python3 scripts/generate-windows-mark.py` из корня репозитория генерирует
`mark_generated.go`; `--check` в CI обнаруживает расхождение исходника и Go.
ICO и PNG рисуются при запуске. В комплекте `murmur.ico` для ярлыков получен
тем же EXE через `--dump-icons`, бинарной копии в репозитории нет.

Глиф, у которого внутренние штрихи сливаются, упрощается **в исходнике** и
перегенерируется, а не правится внутри продукта. Проверяются все пять семантических
состояний на 32 px, белые пиксели замка и внутренней волны, красный сигнал,
комбинации непрочитанного и обновления. Grey и yellow используют один серый idle;
точная причина остаётся в локализованной подсказке и меню. Ready теперь фиолетовый,
failed красный; имена `green.ico` и `yellow.ico` сохранены для отладочного дампа.

Лаунчер создаёт пользовательские ярлыки в «Пуске» и на рабочем столе. Повторный
вызов проверяет сохранённые профиль, путь, PID, время создания и Windows session,
затем открывает меню того же процесса. Видимость в основной части панели остаётся
выбором пользователя Windows; принудительного изменения Explorer нет. Выход из
значка требует подтверждения с Cancel по умолчанию и объяснением второго входа.

## Проверка

```
go test ./...
```

Правило цвета проверяется на образцах, включая устаревший снимок, незнакомую версию
схемы и пустой статус.

Проверка копирования диагностики читает настоящий Windows clipboard и требует
точного JSON, включая кириллицу и emoji. На выделенном тестовом пользователе:

```powershell
$env:MURMUR_TRAY_CLIPBOARD_TEST = '1'
go test -run TestClipboardDiagnosticsAreExactJSON -v
```

Тест заменяет и затем очищает буфер обмена; без этой переменной он явно пропускается.
Windows CI включает его на одноразовом раннере. Для копирования значок использует
штатный Windows PowerShell в STA-режиме, без загрузки профиля, через ограниченный
по времени скрытый процесс; текст передаётся отдельно от команды.

## Проверка обновлений

Меню **Updates** читает общий `murmur updates check --json`: сравнение версий,
HTTP, кеш и настройки остаются в CLI. Проверка запускается в фоне при старте и
через шесть часов после завершения предыдущей; управление службой её не ждёт.
Команда **Check for updates now / Проверить обновления сейчас** запускает проверку
сразу через тот же CLI. Пока она выполняется, пункт показывает ход проверки и
недоступен для повторного нажатия; затем доступны результат, его время или причина
отказа. Команда сохраняет настройки приватности и может показать результат из кеша
с его возрастом. Она не включает отключённые проверки и не устанавливает обновление.
Отдельная фиолетовая стрелка в правом нижнем углу означает доступный релиз;
базовое состояние и красная точка непрочитанного сохраняются.

В меню видны объявленная версия, результат, время последней сетевой попытки,
возраст кеша и код причины отказа. Неизвестный или просроченный ответ не разрешает
открыть релиз. **Open release page** по явному нажатию открывает только HTTPS-страницу
релиза `alexfrmn/murmur` на GitHub. Скачивания, установки и перезапуска нет.
Версия CLI не доказывает, что исходники совпадают с тегом или живым демоном.

Проверку можно отключить через **Disable update checks** и вернуть через **Enable
update checks**. Настройка сохраняется общим CLI для текущего пользователя;
`MURMUR_UPDATE_CHECK=0` имеет приоритет и блокирует сетевые проверки в общем CLI,
включая ручной запуск и таймер. Ручная команда остаётся доступной для получения
состояния «проверки отключены»: CLI не обращается к сети и не меняет настройку.
Переключатели enable/disable при этом недоступны. Сетевой запрос, когда он разрешён,
сообщает GitHub IP-адрес и факт
использования проверяющего клиента; профиль, ключи и учётные данные не отправляются.
Подробный контракт и ограничения: [update-check.md](../../docs/update-check.md).

## Связанные файлы

- `CONTRACT.md` — схема `status --json` и `doctor --json` с правилом вывода цвета.
- `SPIKE-LOG.md` — лог прохождения с временем на каждом этапе и граблями.

## Образцы как общий прогон для двух реализаций

Каждый образец в общем `contracts/setup/v1/fixtures/` несёт рядом со входом
ожидаемый вердикт. Go, Swift и движок читают эти файлы напрямую; локальных копий нет:

```json
"$stamp": "now",
"$expect": { "level": "grey", "unread": true, "code": "service.stopped" }
```

Служебные ключи с `$` значок не читает — незнакомые поля JSON пропускаются, и файл
остаётся валидным документом состояния. Читает их прогон.

**Зачем это так.** Образец, несущий только вход, не годится для сверки реализаций:
ожидание тогда живёт внутри теста каждой платформы, две реализации читают один вход
по-разному и обе честно проходят свои проверки. Ожидание обязано лежать в образце.

**Сверяется код причины, а не текст.** Формулировки на разных платформах разойдутся
неизбежно. Коды устойчивы: `ok`, `service.stopped`, `service.unknown`, `service.failed`,
`outbox.undelivered`, `wake.fault`, `wake.pending`, `broker.unauthorized`,
`broker.unreachable`, `peers.none`, `peers.unpaired`, `unmeasured`, `snapshot.stale`,
`snapshot.future`, `snapshot.unparsable`, `schema.unknown`, `status.unavailable`.

**`$stamp` задаёт дату снимка на момент прогона:** `now`, `now-5m`, `now+1h`, `as-is`.
Без этого поля образцы протухают, а константа из будущего в файле молча выключает
проверку свежести — так и было в первой версии, и три состояния из четырёх проверялись
при неработающей проверке возраста.

Прогон проверен на способность падать: подменённое ожидание валит сборку.

### Перечень недостающих полей в ожидании

Код `unmeasured` сам по себе для сверки реализаций недостаточен: три разных образца
возвращают его, недосчитавшись разного. Две реализации могут сойтись цветом и кодом,
а человек на Windows и на Mac прочитает разные слова о том, чего не хватило. Поэтому
ожидание несёт рядом с кодом перечень:

```json
"$expect": {
  "level": "grey", "unread": true, "code": "unmeasured",
  "missing": ["журнал отказов отправки (файл журнала занят)"]
}
```

Сравнивается как множество, без учёта порядка.
