## Выбор технологии

Go + `fyne.io/systray`. Аргумент машинный: `go1.26.3` стоит и собирает за три секунды,
из .NET на машине только SDK 3.1.426, снятый с поддержки. Подъём на .NET 8 ради
`NotifyIcon` означал скачать SDK и отдать под это заметную часть двухчасового окна.

Цена упаковки: один статический бинарь 3.18 МБ, внешних зависимостей при запуске нет,
установщик не нужен — файл можно положить куда угодно и запустить. Для сравнения,
self-contained сборка .NET дала бы 60–70 МБ.

Чего Go стоит: меню трея описывается императивно, без разметки; подменю есть, иконок в
пунктах меню нет; всплывающие уведомления Windows пришлось бы делать отдельно через
API, `systray` их не даёт.

## Грабли

1. **`sh` на чистой Windows нет.** `scripts/wake-drain-claude.sh` там не работает вовсе;
   рабочий путь — `.mjs`-порт. В документации это описано, но человек, идущий по
   README сверху вниз, спотыкается об это первым.
2. **`clip.exe` и кириллица.** Буфер обмена читает stdin как UTF-16LE только при
   наличии BOM. Без него русский текст диагностики приезжает мусором. Обход —
   `utf16LEWithBOM` в `main.go`.
3. **Подсказка трея обрезается системой на 127 символах.** Резать нужно по рунам:
   срез по байтам разрывает кириллический символ пополам и Windows рисует ромб.
4. **`-ldflags "-H windowsgui"` отбирает stderr.** Собранный так значок отлаживается
   вслепую. Держу вторую, консольную сборку для диагностики; в PR это отражено.
5. **Значок дважды исчезал** при быстрых перезапусках процесса (kill → сразу запуск),
   при этом процесс оставался жив. В контролируемом прогоне — смена четырёх состояний
   подряд на одном процессе — не воспроизвелось, `stderr` библиотеки чист. **Причина не
   установлена**, записываю как открытый вопрос, а не как закрытый дефект.
6. **Службы Windows как таковой ещё нет.** Сегодняшняя схема на этой машине — задача
   Планировщика `MurmurDaemon` с обёрткой `.cmd`. Она переживает перезагрузку и при
   этом не отдаёт наружу ни статуса, ни кода выхода: `schtasks /query` говорит
   «Running» и про упавший внутри node ничего не знает. Это и есть причина городить
   настоящую службу.
