# Murmur для macOS — исследовательский прототип

Нативный `NSStatusItem` и обычное окно с данными из общего Murmur CLI. Окно
открывается при запуске и повторном открытии `.app`. Клик по значку или глобальное
сочетание **⌃⌥⌘M** открывает и скрывает окно. Правый клик открывает краткое меню.
Службы, профили, проверка состояния и обновлений по-прежнему принадлежат CLI.

## Что работает

Окно организовано по задачам: **Главная · Помощь · Настройки**. Первый экран
объясняет назначение Murmur и предлагает приглашение, путь без приглашения или
открытие прежнего подключения. Профиль объясняется рядом с восстановлением.
FAQ из десяти вопросов доступен до и после настройки; переключение в помощь
сохраняет выбранный шаг первого экрана. Все строки раскрытия — целые кнопки
с состоянием для accessibility, а не маленькие треугольники.

Любой выбор существующей папки сначала проходит `recoverSelectedProfile` и
свежую проверку identity через CLI. Приложение показывает найденного агента и
просит открыть подключение; только после этого сохраняет preferences. При
отказе или отмене прежняя папка и identity остаются выбранными. Проверка не
повторяет `init`/`join`, не запускает службу и не меняет файлы профиля.

Ошибка статуса больше не оставляет бесконечное «Проверяем…». Диагностика
показывает первую причину и следующий шаг, технические строки доступны отдельно.
Успешный `doctor` не выдаётся за ответ AI-помощника. Дата обновлений читаема,
возможность возврата кеша объяснена рядом с кнопкой проверки.

Это первая итерация UX. Настройка MCP клиента из GUI и наблюдение реального
ответа AI пока не реализованы; FAQ объясняет, где продолжать работу. Встроенная
поставка Node.js, безопасный общий сервер, notarization и native Windows UX
не входят в эту итерацию. Патч Copy diagnostics R2 остаётся отдельным.

- Разбор `status --json` и `doctor --json`; общий цветной логотип и независимая
  красная точка непрочитанного. Первый путь — вход по приглашению; второй —
  создание профиля для своего сервера. Существующий профиль можно выбрать отдельно.
- Серый при неполном измерении; известная ошибка остаётся видимой даже при сбое
  другого источника. Последние ошибки и число перезапусков сохраняются текстом.
- Таймауты, ограничение размера ответа, абсолютный путь к CLI и отдельные argv.
- Статус каждые 15 секунд. Для нового профиля `doctor` запускается по явной кнопке
  проверки подключения; при обычном открытии ранее настроенного профиля — также при старте.
- Копирование краткой диагностики. Исходные конфиги, сообщения, ключи и сырой stderr
  в буфер не попадают. Для ненулевого выхода CLI показывается первая строка причины
  (до 180 символов); строки с признаками credentials/URL скрываются.
- Демонстрационный режим `--demo`, явно помеченный и не обращающийся к Murmur.
- Выбор одной папки профиля, общей для статуса, диагностики и управляющих команд.
  До свежего статуса с подтверждённым `agentId` действия недоступны с объяснением.
- Пауза/возобновление передачи агенту через `wake pause|resume` **без `--apply`**.
  Меню отдельно показывает настройку, действующий режим и необходимость перезапуска.
  Непрочитанные и ожидающие передачи сообщения остаются видимыми; неизвестное
  измерение не превращается в ноль. Значок следует общему визуальному контракту.
- Запуск/остановка установленной службы через CLI. Папка логов получается свежим
  `logs path --json`: проверяется профиль/агент и открывается только возвращённый
  каталог. Команда требует setup engine с поддержкой `murmur.logs/1`.

Вход по приглашению вызывает `join`, создание своего профиля — `init`.
Приложение выбирает новую приватную папку и уникальное имя; для своего сервера
имя можно изменить. Адрес сервера и необязательный файл доступа вводит пользователь,
публичного сервера по умолчанию нет. Ответный файл приглашения показывается в Finder.
Ни один из этих шагов не считается доказательством соединения или live wake.

После создания отдельная кнопка устанавливает и запускает службу через CLI:
`status → service install → status → service start`. Между изменениями проверяется
тот же `agentId`; ключи не создаются заново. Шаги настройки и ссылка на ответный файл
сохраняются при повторном открытии. Создание само не запускает службу или `doctor`.

Недоступный просмотр inbox не показывается. `mark-read` вместо него не вызывается.
`SMAppService.mainApp` подключён к переключателю входа в систему, но регистрация,
выход/вход и перезагрузка не проверены. При запуске регистрация не выполняется.

## Сборка и проверка

Незавершённая первичная настройка хранится в приватном `pending-setup.json` рядом
с папками профилей. До `init`/`join` сохраняется выбранная личность; успешная запись
и завершение команды фиксируются отдельно. После сбоя или перезапуска продолжение
проверяет прежний профиль через CLI `status`, не повторяя создание. Стереть запись
о пустой попытке можно только после подтверждённого завершения команды и проверки
отсутствия файлов; файлы профилей и ответов приложение при этом не удаляет.
Старые непустые UUID-папки показываются до выбора создания отдельного профиля,
включая папки с незавершённой записью. Обнаружение читает только метаданные;
личность и состояние выбранной папки затем проверяет CLI.
Повреждённую или неопределённую запись можно явно сбросить через подтверждение
в окне: `renamex_np(RENAME_EXCL)` сохраняет её копию в приватном каталоге
`saved-setup-records`. Никакие профильные файлы не перемещаются и не удаляются.
Ссылки и чужие/необычные файлы сброс не принимает. Перед сбросом сохраняется
обязательный выбор способа продолжения, действующий и после рестарта; автоматического
создания или повторного CLI-вызова нет.
После создания, переименования и очистки записи синхронизируется содержащий каталог;
при создании новых каталогов — каждый новый каталог и его родитель. Ошибка исходной
синхронизации останавливает операцию до CLI. Проверены реальные syscall на APFS
и восстановление после прерывания процесса; гарантия сохранности при потере питания
этим не заявляется ([ограничение fsync в документации Apple](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html)).
Выбор старой приватной папки восстанавливает setup steps после свежего CLI status:
сохраняется прежняя личность, находится исходный ответный файл и остаётся доступна
установка/запуск службы. Сам выбор не выполняет init/join, service или doctor.
В режиме восстановления это относится и к списку, и к выбору папки через диалог:
сначала читается status, затем сохраняется выбор и снимается ограничение. Ошибка
оставляет выбор восстановления открытым. Файловый псевдоним приватного профиля
приводится к прежней папке, чтобы восстановились исходный reply и setup steps.
У внешнего профиля сохраняется выбранный пользователем путь, включая alias и явное
имя службы: CLI выводит имя службы из текстового data-dir, поэтому его нельзя тихо
заменять realpath. Канонический путь используется только для распознавания приватного
профиля приложения.

На редком пути записи журнала после успешного fsync явно запрашивается F_FULLFSYNC
для файлов и каталогов. Только неподдерживаемая операция (EINVAL/ENOTSUP) оставляет
уже выполненный fsync; настоящие ошибки записи не скрываются и до CLI останавливают
создание. Копируемая диагностика показывает последний результат и сохраняет факт
предыдущего fallback даже после успешной полной синхронизации и перезапуска.
Это усиление одного звена, не гарантия атомарности config/reply/preferences при потере
питания. Проверка поддержки и времени на отдельной APFS fixture не заменяет power-cut test.
При повторе после ошибки синхронизации существование созданной папки не считается
успехом: до CLI снова синхронизируется весь путь до границы файловой системы. Это
повторяет и неуспешный сброс родителя, включая несколько уже созданных каталогов;
новый экземпляр журнала после перезапуска проходит ту же проверку.

Нужны macOS 13+, Swift 6 и Apple Command Line Tools. Проверено на arm64, macOS
26.6.2, Swift 6.4. Полный Xcode не установлен. Поэтому проверки работают как
Foundation executable; XCTest в этой установке Command Line Tools отсутствует.

```sh
cd apps/macos-menubar
./scripts/build-app.sh
```

Скрипт сначала выполняет `MurmurProbeChecks` на **общих**
`contracts/setup/v1/fixtures`, затем собирает приложение. Ошибка примера останавливает
упаковку. CI `macOS menu bar contract` запускает тот же скрипт. Набор закреплён на
`44b882d48f0139592dea9bd65d89b8a3f11c23cc` (packet one); ожидания берутся из `$expect`,
дата — по политике `$stamp`, сравниваются цвет, точка, код, множество недостающих
полей и карта устойчивых причин `missingWhy`. Проверки doctor читают `$expect.valid`:
после отказа каждый следующий этап обязан быть пропущен с `blocked-by:<этап>`.
Отдельные отрицательные контроли проверяют, что изменённое ожидание ломает проверку.
Отсутствующее поле, неверный тип и отрицательный счётчик имеют разные коды ошибок;
при ошибке схемы непрочитанное не выводится. Незнакомые дополнительные поля допустимы.
В каталоге приложения копий fixtures нет. При интеграции общий каталог должен быть
включён из ветки setup engine; отсутствие каталога приводит к ошибке проверки.

Результат — `dist/Murmur Spike.app`, подписанный локальной ad-hoc подписью.
Developer ID, notarization, Intel/universal build и установка на чистую машину
не проверены. Этот способ сборки предназначен разработчику, не конечному пользователю.

Поиск CLI: абсолютный `MURMUR_BIN`, затем совместимый `MURMUR_CLI`, затем стандартные
пути Homebrew и `~/.local/bin/murmur`. Приложение не читает SQLite или секретный
`agent-config.json`. Отсутствующий CLI даёт серый статус с объяснением.

Выберите существующую папку через «Открыть прежнее подключение». Подтверждённый выбор сохраняется
в настройках приложения. При запуске можно явно задать абсолютный `MURMUR_DATA_DIR`
и, для нестандартного имени службы, `MURMUR_SERVICE_NAME`. Эти значения имеют приоритет
над сохранённым выбором; меню показывает выбранные папку и имя службы. Общий `DATA_DIR`
и рабочая папка процесса не выбирают профиль автоматически. Повторный выбор папки
через меню использует стандартное имя службы CLI.

Исполняемый файл CLI закрепляется при выборе профиля. Каждая управляющая команда
сначала заново запрашивает статус и сверяет `agentId`; смена агента требует повторного
выбора. Дочерний процесс получает отдельные argv, фиксированный PATH и ограниченное
окружение, без унаследованных переопределений профиля/SQLite/Node. Таймауты: статус и
путь логов — 5 секунд, действие — 20, doctor — 30. После действия, включая ошибку или
таймаут, приложение заново получает статус; автоматического повтора и перезапуска
нет. Ответ `source=configured` для логов не доказывает, куда пишет живой процесс.

`MurmurProbeChecks` также проверяет общий профиль/argv, отсутствие shell-интерпретации,
смену и устаревание identity, таймауты/ошибки/лимиты, отсутствие повторных мутаций и
отклонение неподтверждённых каталогов логов. Для фактической работы нужны установленная
служба этого профиля и доступный CLI; эти проверки не заменяют визуальную приёмку меню.

## Проверка обновлений

Значок асинхронно вызывает общий `murmur updates check --json` после старта и через
6 часов после завершения предыдущей проверки. Она не участвует в блокировке status,
doctor или управления службой. Данные, сравнение версий, сетевой запрос и кеш целиком
принадлежат CLI; приложение не выводит путь кеша из профиля. Выбор другого агента
не запускает ещё один запрос обновлений.

Отдельная фиолетовая метка со стрелкой означает доступный стабильный релиз. Цвет
здоровья и красная точка непрочитанного сохраняются независимо. В меню показаны
объявленная версия продукта, причина результата, время последней попытки и успеха,
возраст кеша. Ошибка сети/CLI/схемы остаётся неизвестным результатом. Истёкший ответ
не даёт активную ссылку или метку доступного обновления.

Источник версии — корневой `package.json.version`, а сравнение — номер релиза.
Это не проверка совпадения исходников/артефакта с Git-тегом. Пререлизы отфильтровывает
общий CLI. Приложение повторно проверяет, что действие ведёт только на HTTPS-страницу
`github.com/alexfrmn/murmur/releases/tag/...`, и открывает её по явному клику.
Скачивание, исполнение, установка и перезапуск не выполняются.

Проверка включена по умолчанию. Неавторизованный запрос сообщает GitHub IP и факт
использования Murmur; эта информация указана в меню. Пункты включения/отключения
сохраняют выбор через `updates enable|disable --json`, затем читают эффективное
состояние. Проверка при отключении локальная и не обращается к GitHub. Общая настройка
и кеш относятся к текущему OS-пользователю, а не агенту. `MURMUR_UPDATE_CHECK=0`
передаётся дочернему CLI как принудительное отключение; другое значение переменной
не передаётся. Токены GitHub и остальные запрещённые переопределения окружения не
наследуются. Запрос ограничен CLI до 4 секунд, сам subprocess — до 6 секунд.

Нужен CLI с контрактом `murmur.updates/1` (PR179). Старый CLI оставляет обновления
неизвестными с причиной; работа профиля продолжается. Новые unit-проверки покрывают
три состояния, обязательные поля и типы, URL allowlist, кеш/время, opt-out, argv,
предпочтения, ошибки и лимиты. GUI-приёмка метки и открытия браузера пока не проведена.

Упаковка и проверка общего Go-ядра из Windows-прототипа:

```sh
MURMUR_GO_BIN=/absolute/path/to/go ./scripts/build-shared-go-smoke.sh
```

Эксперимент фиксирован на `a9dcb7200561bb9c55e2b21a22dedf8266703922`, использует
`fyne.io/systray v1.11.0` и 27 строк Darwin entrypoint. Подтверждает переносимость
модели/иконок и сборки, но не паритет функций. Более ранний `go-smoke/` использует
другую библиотеку (`getlantern`); его зависимости не описывают Windows-прототип.

## Знак и второй вход

Источник рисунка — `contracts/visual/murmur-mark.svg`. Генератор
`scripts/generate-mark.py` переводит ограниченный SVG-контракт в Core Graphics и
сохраняет `sourceSHA256`; неизвестная геометрия приводит к ошибке. Все три пути
сборки запускают `--check`, а проверки сверяют хеш с общим исходником. Поменяв
рисунок, нужно перегенерировать Swift, затем проверить 18/32 px и обе плотности.

В строке меню — 18 pt, готовые растры 1x/2x, `isTemplate = false`: цветной круг
несёт собственный фон. В шапке окна — тот же логотип 40 pt. `unknown`, `stopped`,
`paused`, `offline` имеют серый знак; точное состояние остаётся в тексте. Ошибка
красит весь круг, непрочитанное добавляет точку, обновление — стрелку. Наложения
не заменяют здоровье основного знака. Tooltip и VoiceOver называют состояние,
непрочитанное и обновление словами.

`autosaveName = "Item-0"` сохраняет пользовательскую позицию Command-перетаскивания
и использует имя прежнего единственного `MenuBarExtra`. Приложение не меняет
системные отступы и не пытается определить скрытость через `isVisible`: этот флаг
не доказывает, что значок виден возле выреза камеры. Окно и горячая клавиша работают
независимо от места значка. Если сочетание уже занято, подвал сообщает об этом и
предлагает открыть `.app` через Finder. Для регистрации сочетания приложению не
нужен Accessibility grant.

Native source acceptance на macOS 26.6.2 проверяет первое окно, повторное открытие,
глобальную клавишу из Finder, краткое меню до профиля, явное переключение EN/RU и
выбор одноразового профиля. Ответы CLI в этой GUI-проверке синтетические; она не
доказывает живую службу или доставку. Рендер-проверки отдельно покрывают размер,
цвет, читаемость белого глифа и независимость меток. Release acceptance должна быть
повторно привязана к опубликованному артефакту. Вход в систему и перезагрузка не
проверены.

## Mac-служба

`packages/setup/src/platform/darwin.ts` реализует общий `PlatformAdapter`.
`install` пишет приватный управляемый plist, `start` использует per-user launchd,
`stop` выгружает службу. Статус подтверждает store по открытому FD, а не по переменной
окружения. Старый production профиль автоматически не мигрируется.

`claude-desktop` означает MCP-конфиг чат-приложения Claude. Вкладка Claude Code
использует конфигурацию Claude Code, а не `claude_desktop_config.json`.
Нестандартный `CLAUDE_CONFIG_DIR` пока возвращает неизвестный путь с объяснением;
проверять его и менять MCP-конфиги должен общий setup engine.
