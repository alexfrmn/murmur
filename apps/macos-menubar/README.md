# Murmur для macOS — исследовательский прототип

Нативный значок SwiftUI `MenuBarExtra` с данными из общего Murmur CLI. Обычного окна,
Electron и WebView нет. Это прототип для выбора технологии и проверки контракта,
а не готовый установщик для распространения.

## Что работает

- Разбор `status --json` и `doctor --json`, цвета и независимая синяя точка.
- Серый при неполном измерении; известная ошибка остаётся видимой даже при сбое
  другого источника. Последние ошибки и число перезапусков сохраняются текстом.
- Таймауты, ограничение размера ответа, абсолютный путь к CLI и отдельные argv.
- Проверка `doctor` при старте и по кнопке, статус каждые 15 секунд.
- Копирование краткой диагностики. Исходные конфиги, сообщения, ключи и сырой stderr
  в буфер не попадают. Для ненулевого выхода CLI показывается первая строка причины
  (до 180 символов); строки с признаками credentials/URL скрываются.
- Демонстрационный режим `--demo`, явно помеченный и не обращающийся к Murmur.
- Выбор одной папки профиля, общей для статуса, диагностики и управляющих команд.
  До свежего статуса с подтверждённым `agentId` действия недоступны с объяснением.
- Пауза/возобновление передачи агенту через `wake pause|resume` **без `--apply`**.
  Меню отдельно показывает настройку, действующий режим и необходимость перезапуска.
  Непрочитанные и ожидающие передачи сообщения остаются видимыми; неизвестное
  измерение не превращается в ноль. Правила цвета не меняются.
- Запуск/остановка установленной службы через CLI. Папка логов получается свежим
  `logs path --json`: проверяется профиль/агент и открывается только возвращённый
  каталог. Команда требует setup engine с поддержкой `murmur.logs/1`.

Кнопка inbox отключена: в CLI пока нет просмотра inbox. `mark-read` вместо него
не вызывается. Установка службы и создание профиля выполняются общим CLI.
`SMAppService.mainApp` подключён к переключателю входа в систему, но регистрация,
выход/вход и перезагрузка не проверены. При запуске регистрация не выполняется.

## Сборка и проверка

Нужны macOS 13+, Swift 6 и Apple Command Line Tools. Проверено на arm64, macOS
26.6.2, Swift 6.4. Полный Xcode не установлен. Поэтому проверки работают как
Foundation executable; XCTest в этой установке Command Line Tools отсутствует.

```sh
cd apps/macos-menubar
./scripts/build-app.sh
```

Скрипт сначала выполняет `MurmurProbeChecks` на **общих**
`contracts/setup/v1/fixtures`, затем собирает приложение. Ошибка примера останавливает
упаковку. CI `macOS menu bar contract` запускает тот же скрипт. Набор закреплён на
`44b882d48f0139592dea9bd65d89b8a3f11c23cc` (packet one); ожидания берутся из `$expect`,
дата — по политике `$stamp`, сравниваются цвет, точка, код, множество недостающих
полей и карта устойчивых причин `missingWhy`. Проверки doctor читают `$expect.valid`:
после отказа каждый следующий этап обязан быть пропущен с `blocked-by:<этап>`.
Отдельные отрицательные контроли проверяют, что изменённое ожидание ломает проверку.
Отсутствующее поле, неверный тип и отрицательный счётчик имеют разные коды ошибок;
при ошибке схемы непрочитанное не выводится. Незнакомые дополнительные поля допустимы.
В каталоге приложения копий fixtures нет. При интеграции общий каталог должен быть
включён из ветки setup engine; отсутствие каталога приводит к ошибке проверки.

Результат — `dist/Murmur Spike.app`, подписанный локальной ad-hoc подписью.
Developer ID, notarization, Intel/universal build и установка на чистую машину
не проверены. Этот способ сборки предназначен разработчику, не конечному пользователю.

Поиск CLI: абсолютный `MURMUR_BIN`, затем совместимый `MURMUR_CLI`, затем стандартные
пути Homebrew и `~/.local/bin/murmur`. Приложение не читает SQLite или секретный
`agent-config.json`. Отсутствующий CLI даёт серый статус с объяснением.

Выберите существующую папку через «Выбрать папку профиля…». Последний выбор сохраняется
в настройках приложения. При запуске можно явно задать абсолютный `MURMUR_DATA_DIR`
и, для нестандартного имени службы, `MURMUR_SERVICE_NAME`. Эти значения имеют приоритет
над сохранённым выбором; меню показывает выбранные папку и имя службы. Общий `DATA_DIR`
и рабочая папка процесса не выбирают профиль автоматически. Повторный выбор папки
через меню использует стандартное имя службы CLI.

Исполняемый файл CLI закрепляется при выборе профиля. Каждая управляющая команда
сначала заново запрашивает статус и сверяет `agentId`; смена агента требует повторного
выбора. Дочерний процесс получает отдельные argv, фиксированный PATH и ограниченное
окружение, без унаследованных переопределений профиля/SQLite/Node. Таймауты: статус и
путь логов — 5 секунд, действие — 20, doctor — 30. После действия, включая ошибку или
таймаут, приложение заново получает статус; автоматического повтора и перезапуска
нет. Ответ `source=configured` для логов не доказывает, куда пишет живой процесс.

`MurmurProbeChecks` также проверяет общий профиль/argv, отсутствие shell-интерпретации,
смену и устаревание identity, таймауты/ошибки/лимиты, отсутствие повторных мутаций и
отклонение неподтверждённых каталогов логов. Для фактической работы нужны установленная
служба этого профиля и доступный CLI; эти проверки не заменяют визуальную приёмку меню.

## Проверка обновлений

Значок асинхронно вызывает общий `murmur updates check --json` после старта и через
6 часов после завершения предыдущей проверки. Она не участвует в блокировке status,
doctor или управления службой. Данные, сравнение версий, сетевой запрос и кеш целиком
принадлежат CLI; приложение не выводит путь кеша из профиля. Выбор другого агента
не запускает ещё один запрос обновлений.

Отдельная фиолетовая метка со стрелкой означает доступный стабильный релиз. Цвет
здоровья и синяя точка непрочитанного сохраняют прежние правила. В меню показаны
объявленная версия продукта, причина результата, время последней попытки и успеха,
возраст кеша. Ошибка сети/CLI/схемы остаётся неизвестным результатом. Истёкший ответ
не даёт активную ссылку или метку доступного обновления.

Источник версии — корневой `package.json.version`, а сравнение — номер релиза.
Это не проверка совпадения исходников/артефакта с Git-тегом. Пререлизы отфильтровывает
общий CLI. Приложение повторно проверяет, что действие ведёт только на HTTPS-страницу
`github.com/alexfrmn/murmur/releases/tag/...`, и открывает её по явному клику.
Скачивание, исполнение, установка и перезапуск не выполняются.

Проверка включена по умолчанию. Неавторизованный запрос сообщает GitHub IP и факт
использования Murmur; эта информация указана в меню. Пункты включения/отключения
сохраняют выбор через `updates enable|disable --json`, затем читают эффективное
состояние. Проверка при отключении локальная и не обращается к GitHub. Общая настройка
и кеш относятся к текущему OS-пользователю, а не агенту. `MURMUR_UPDATE_CHECK=0`
передаётся дочернему CLI как принудительное отключение; другое значение переменной
не передаётся. Токены GitHub и остальные запрещённые переопределения окружения не
наследуются. Запрос ограничен CLI до 4 секунд, сам subprocess — до 6 секунд.

Нужен CLI с контрактом `murmur.updates/1` (PR179). Старый CLI оставляет обновления
неизвестными с причиной; работа профиля продолжается. Новые unit-проверки покрывают
три состояния, обязательные поля и типы, URL allowlist, кеш/время, opt-out, argv,
предпочтения, ошибки и лимиты. GUI-приёмка метки и открытия браузера пока не проведена.

Упаковка и проверка общего Go-ядра из Windows-прототипа:

```sh
MURMUR_GO_BIN=/absolute/path/to/go ./scripts/build-shared-go-smoke.sh
```

Эксперимент фиксирован на `a9dcb7200561bb9c55e2b21a22dedf8266703922`, использует
`fyne.io/systray v1.11.0` и 27 строк Darwin entrypoint. Подтверждает переносимость
модели/иконок и сборки, но не паритет функций. Более ранний `go-smoke/` использует
другую библиотеку (`getlantern`); его зависимости не описывают Windows-прототип.

## Предел проверки интерфейса

Обе `.app` запускаются как процессы. Доступный native UI inspector возвращает
`timeoutReached` при выборе приложений без обычного окна. Видимость значка,
раскрытие меню, клики, контрастность и поведение возле выреза экрана не подтверждены.
Процесс в списке не считается визуальной приёмкой.

Ручная проверка: открыть `.app`, найти значок в строке меню, раскрыть меню, пройти
все состояния в `--demo`, проверить серый без CLI, убедиться, что «Выход» закрывает
только значок. Отдельно проверить светлую/тёмную тему, доступность VoiceOver,
перезапуск, вход в систему и отсутствие окон/Dock icon. Это список оставшейся
приёмки, а не выполненные проверки.

## Mac-служба

`packages/setup/src/platform/darwin.ts` реализует общий `PlatformAdapter`.
`install` пишет приватный управляемый plist, `start` использует per-user launchd,
`stop` выгружает службу. Статус подтверждает store по открытому FD, а не по переменной
окружения. Старый production профиль автоматически не мигрируется.

`claude-desktop` означает MCP-конфиг чат-приложения Claude. Вкладка Claude Code
использует конфигурацию Claude Code, а не `claude_desktop_config.json`.
Нестандартный `CLAUDE_CONFIG_DIR` пока возвращает неизвестный путь с объяснением;
проверять его и менять MCP-конфиги должен общий setup engine.
