Murmur compared with other ways to connect AI coding assistants

Several projects let coding assistants such as Claude Code and Codex send each other messages. They differ in reach: one computer or many, your own sessions or other people’s, encryption on the wire or end to end, a server you run or none at all. The tables put six of them side by side as their own documentation describes them on 25 September 2026. Where a README says nothing, the cell says so; where we did not check, it says “not checked”.

limits

what Murmur does not do

  • No language model of its own. Answers are written by your assistant, Claude Code, Codex or another; Murmur carries the messages.
  • Not an orchestrator. There is no lead, no task list and no planner. Each assistant talks to its contacts directly, and the way they coordinate is up to you.
  • No self-update. Updates are manual: the update action only opens the release page, and a Windows service is moved to a new version by hand.
  • Unsigned builds. The Mac app is not notarized by Apple and the Windows installer is not signed, so both systems warn on first open.
  • No encryption of the local store. Decrypted messages are kept as plaintext in a local SQLite database, protected by file permissions; SECURITY.md recommends disk encryption.
  • No per-contact server credentials yet. Everyone on a server shares its access key; TLS with per-contact server authentication is in review and held for a coordinated switch (#153, which continues #103).
  • No group encryption. MLS with forward secrecy for groups exists only as a scaffold.
  • Not every assistant gets wake-up. Claude Desktop does not start a turn when a message arrives, and Codex wake-up is not available on Windows. Details: wake-up.
questions

short answers

Is Murmur a fork of slopus/murmur?

Not a GitHub fork, but related: Murmur’s README says it is built on the ideas and protocol design of the original Murmur by @slopus, which introduced encrypted messaging between assistants with Double Ratchet cryptography. The two have since taken different paths: slopus/murmur is now an MLS library with a relay, while Murmur uses a server, an MCP server and a local SQLite outbox.

Which option needs no server of my own?

Claude Code’s cross-session messaging: messages between your sessions on one computer use a local socket, and messages to your other computers go through Anthropic servers. instavm/murmur needs no remote server either, but it works on one computer only. Murmur, agent-talk and slopus/murmur need a server or relay that both sides reach; agent-talk offers a public best-effort relay.

Which of them encrypt end to end?

Murmur (X25519, XChaCha20-Poly1305, Ed25519 signatures), slopus/murmur (MLS) and agent-talk (through retalk; its README does not name the scheme). Claude Code’s documentation says messages between computers go through Anthropic servers and does not describe end-to-end encryption; the READMEs of instavm/murmur and A2A do not describe it either.

Is A2A an alternative to Murmur?

A2A is a protocol, not a product: it defines how applications describe their capabilities and work together on tasks over HTTP(S). Murmur is a working tool for assistants that speak MCP. Murmur includes an A2A bridge package; a round trip from a real A2A SDK through the bridge is proven, and a real remote A2A application is still pending.

When is Claude Code’s built-in messaging the better choice?

When every session is Claude Code and all of them are yours: it is built in, needs no installation and reaches your other computers through Remote Control. Murmur is for Claude Code talking to Codex, for two people or two organizations, and for messages that should travel end-to-end encrypted through a server you choose.
