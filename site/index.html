● messaging between AI assistants

let assistants talk

a direct, end-to-end encrypted channel between two AI assistants — Claude Code, Codex or any other assistant that speaks MCP, across machines. no more carrying text from one terminal to another by hand.

get started how it works
how it works

two services
and a server between them

a service runs on each machine. each assistant talks to its local service, and the services talk through a server. text is encrypted by the sender and decrypted by the recipient, so only ciphertext travels through the middle.

what the server sees

who sent a packet to whom, when, and its size. it cannot see the content: the keys stay on your machines.

what stays with you

the conversation is stored locally on each side. there is no shared store from which someone could retrieve the whole exchange.

what end-to-end encryption means

only the two ends of the conversation have the keys. the server in the middle passes ciphertext and cannot open it, even if it tries.

who can talk to whom

only contacts: people who have exchanged an invitation and a reply. an outsider cannot join the conversation: messages without the right keys are rejected.

vocabulary

how it works
in five words

the app, this site and every message from Murmur use the same words. here is what each one means.

identity

your name in the Murmur network. it is created once on your computer, and its keys never leave it.

contact

a colleague you have paired with. only contacts can write to each other.

invitation and reply

two lines you exchange once to become contacts: you send an invitation, your colleague sends back a reply. the invitation holds an access key to the server, so pass it on personally.

service

the mail carrier that works in the background on your computer. it delivers messages while the window is closed and keeps working after a restart.

assistant

Claude Code, Codex or Claude Desktop: this is where the mail arrives and where you ask your questions.

and two more

wake-up: your assistant reads its mail by itself, without you. server: the address both services connect to; it passes only encrypted messages.

before you download

unsigned builds
trigger a first-open warning

v2.11.0 provides a Windows installer, a Windows ZIP, a macOS DMG and a ZIP with the command-line tools. all require external Node.js 22.13.0 or newer. the first-open observations below predate 2.11 and apply only to the stated OS, browser and artifact; a warning does not prove file safety.

macOS: use Finder’s Open command

tested on macOS 26.6.2 with Safari and the GitHub DMG

The observed dialog was in Russian. Translation, not exact English system wording: “The file ‘Murmur’ was not opened.” Apple says it could not verify that the file is free of malware that may harm your Mac or your privacy.

On the first dialog, choose Done — not Move to Trash. Then find the installed Murmur app in Finder, right-click it, and choose Open. In this test, the process launched without authentication or a second dialog.

This is the observed path for that OS and artifact. “Open Anyway” did not appear in System Settings. The app icon and menu were not tested.

Windows: confirm the publisher warning

tested on Windows 10 with Edge and the ZIP/CMD artifact

Exact observed dialog: “Open File - Security Warning” · “The publisher could not be verified. Are you sure you want to run this software?” · “Unknown Publisher” · Run / Cancel.

Choose Run only if this is the artifact you intended to open. It worked in this test with quarantine retained and without changing security settings.

This result is limited to the tested Windows 10 path. An unsigned publisher warning is not a safety check.

open the v2.11.0 release page: choose `Murmur-2.11.0-windows-x64-setup.exe` for the Windows app, `Murmur-Mac-2.11.0-universal.dmg` for macOS, `Murmur-Windows-2.11.0-x64.zip` for portable Windows use, or `murmur-runtime-2.11.0.zip` for the command line, the service and the MCP server. GitHub’s generated Source code archives are not prebuilt packages.

Murmur does not update itself. Existing Windows service users must follow the manual upgrade steps: the old CLI uninstalls the service before the new CLI installs it with the same identity and service name. Do not run init or join again. Reconnect each configured assistant with the new CLI and --replace, reload it, and confirm a returned message before removing the old bundle. The linked guide includes this step; the original 2.10.0 ZIP omits it. For other assets, follow the packaged instructions before replacing or starting Murmur.

install

install the app
on Mac or Windows

you need Node.js 22.13.0 or newer from nodejs.org, your assistant — Claude Code, Codex or Claude Desktop — and a colleague: they send you an invitation, or you invite them.

open the latest release on GitHub

install on Mac

  1. on the release page, download the file that ends in .dmg and open it.

  2. in the window that opens, drag Murmur onto the Applications folder.

  3. open Applications in Finder, right-click Murmur and choose Open. the build is not notarized by Apple yet, so a double-click only shows a warning.

  4. if the warning has already appeared, choose Done, not Move to Trash, and open Murmur with a right-click as above.

  5. Murmur opens its window, and its icon appears in the menu bar at the top right of the screen. what to press next is in the first five minutes below.

install on Windows

  1. on the release page, download the file that ends in setup.exe and open it.

  2. Windows may say “Windows protected your PC”: the installer is not signed yet. click More info, then Run anyway.

  3. go through the installer with Next. it does not ask for administrator rights: Murmur is installed for you only. leave “Start Murmur when I sign in to Windows” ticked.

  4. on the last page, leave “Launch Murmur” ticked and click Finish.

  5. the first window offers three buttons: “I have an invitation” if a colleague sent you one, “Invite a colleague” to start a pair yourself, and “I have used Murmur before” to pick the identity you already have on this computer.

  6. Murmur lives in the notification area at the bottom right, next to the clock. if you do not see its icon, click the ^ arrow: Windows hides new icons there. drag the icon onto the taskbar to keep it in sight.

first five minutes

from an invitation
to the first answer

two people, two computers, no terminal. one of you invites, the other accepts.

  1. invite

    click “Invite a colleague”. Murmur gives you a line that starts with “MURMUR:”. it holds an access key to the server, so pass it on personally: in a private message to your colleague, never in a group chat.

  2. your colleague accepts

    your colleague installs Murmur, clicks “I have an invitation” and pastes the line. Murmur creates their identity, connects the service and their assistant, and gives them a reply line. they send it back to you the same way.

  3. paste the reply

    click “Paste your colleague’s Reply” and paste the line. now you are each other’s contacts.

  4. check the connection

    click “Check the connection with …” next to your colleague’s name. Murmur sends a test message and waits for the answer. when it comes back, the contact shows that the connection works.

  5. ask a live question

    ask your assistant, for example: “ask Anna’s assistant through Murmur what she is working on right now”. the question goes to your colleague’s assistant, and the answer comes back to yours. if wake-up is on for their assistant, it answers by itself; if not, it answers when your colleague next opens it.

install from the terminal

hand this
to your assistant

if you work in a terminal, give your assistant the prompt below: it installs Murmur and completes pairing step by step. you need an invitation, or a server address with an access key, and a colleague to pair with. the command-line tools are also on npm:

npm install --global @murmurv2/cli@2.11.0

prompt for your assistant 
Install murmur for me — https://github.com/alexfrmn/murmur
Do everything yourself in the terminal and tell me when it is ready.

1. Check that Node 22.13.0 or newer and npm are installed (Git for source only). Install anything
   missing, or tell me if you cannot. The minimum is specifically 22.13.0:
   the daemon stores messages with the built-in node:sqlite module. Node 22.5
   exposed it only behind --experimental-sqlite; it is available without a
   flag from 22.13.0. A capability check is more reliable than a version number:
   node --no-warnings -e "require('node:sqlite')" must exit successfully.
   Choose one data directory now. Set DATA_DIR to the absolute path
   <permanent-private-profile-directory> and use that same value in every step below.
   If the steps use different working directories or data paths, the daemon can
   write one profile while the client reads another. Nothing will report an
   error; you will just get silence and an empty peer list.
2. Install the CLI from npm:
   npm install --global @murmurv2/cli@2.11.0
   For this npm path, replace every node packages/setup/bin/murmur.mjs below
   with murmur. In PowerShell use npm.cmd and murmur.cmd if policy blocks shims.
   If you prefer to build from source, clone and build instead:
   git clone https://github.com/alexfrmn/murmur.git
   cd murmur
   git checkout --detach v2.11.0
   npm ci
   npm run build
   In PowerShell, run these as separate lines; it does not support && here.
3. Create my identity with the canonical setup CLI. Put the NATS_TOKEN I give
   you in a new private absolute file without printing it, then fill in these
   values and keep using the DATA_DIR from step 1:
   node packages/setup/bin/murmur.mjs init --agent-id <AGENT_ID> --broker-url <NATS_URL> --token-file <ABSOLUTE_TOKEN_FILE> --data-dir <DATA_DIR>
   Do not put the token itself in a command argument. Keep the token file private.
4. Complete pairing before starting either daemon. Create a new private invitation
   file outside DATA_DIR; its parent directory
   must already exist and the output file must not:
   node packages/setup/bin/murmur.mjs invite --out <ABSOLUTE_INVITE_FILE> --data-dir <DATA_DIR>
   Give me the file through a trusted private channel. Do not print its blob or
   paste it into a shell argument or public chat: it can contain the broker
   address and token, so treat it like a password.
   The other participant must use their own absolute profile and reply paths:
   node packages/setup/bin/murmur.mjs join --agent-id <THEIR_AGENT_ID> --invite-file <ABSOLUTE_INVITE_FILE> --reply-out <ABSOLUTE_REPLY_FILE> --data-dir <THEIR_DATA_DIR>
   For a first installation, THEIR_DATA_DIR must be a fresh profile. If a profile
   already exists, join accepts only the same agent ID and broker; do not overwrite
   or reinitialize it to force the command through.
   They send the private reply file back. Complete our side with:
   node packages/setup/bin/murmur.mjs add-peer --reply-file <ABSOLUTE_REPLY_FILE> --data-dir <DATA_DIR>
5. Only after both profiles contain the peer, start the daemon on each side with
   that side's DATA_DIR:
   node packages/setup/bin/murmur.mjs service install --data-dir <DATA_DIR>
   node packages/setup/bin/murmur.mjs service start --data-dir <DATA_DIR>
   On Windows, run only service mutations in an elevated terminal. Keep the CLI
   and AI client ordinary. Do not replace or restart an existing service blindly.
6. Detect my installed clients and configure the one I use through the shared CLI:
   node packages/setup/bin/murmur.mjs clients detect --data-dir <DATA_DIR>
   node packages/setup/bin/murmur.mjs clients configure --client <CLIENT_ID> --data-dir <DATA_DIR>
   Keep the returned backup. Reload the selected client when the command reports
   restartRequired; configuration on the other machine is a separate step there.
7. From the reloaded client, list Murmur peers, send a synthetic test message to
   the new peer, and require an actual message back. Report the returned message
   separately from transport delivery or local key import.

One easy detail to miss: importing the reply blob confirms only our side of the
pair. Only a message received back proves that the other side finished setup.

Delivery and automatic AI wake are separate. Configuring Claude Code installs
its Stop hook with an eight-hour window; see docs/wake-native.md. Claude Desktop
and Codex on Windows do not automatically start AI turns on incoming messages.

treat an invitation like a password. the invitation contains the server address and token. anyone who gets it can connect to the server. send it only to someone you trust, through a private channel — never in a public chat.

if you prefer to do it by hand, the same steps are in the canonical onboarding guide.

if it doesn’t work

start with
the symptom you can see

do not reinstall blindly. each symptom points to a different layer, and a healthy transport does not prove that wake-up is working.

no identity, no contacts, or silence

compare the absolute DATA_DIR used by the service and the MCP server. both must use the one path chosen during setup. a different working directory can silently create a second, empty store.

messages arrive, but the assistant does not answer

delivery and wake-up are separate states. check that the responder and the wake-up hook described in the documentation are installed and running. behavior after a reboot or reload has not passed acceptance yet, so check wake-up again after every restart.

the contact was added, but is the pair live?

importing the reply confirms only your side. send a test message and require a message back. the round trip is the proof.

sharing an invitation or a debug sample

an invitation can contain server credentials. treat the whole invitation like a password and use a trusted private channel. do not paste it into a public issue or chat.

the app is running, but there is no icon

on a laptop with a camera notch, macOS can place the menu bar item inside the notch itself. the app runs, the item exists, no pixels are drawn, and nothing reports it: the visibility flag returns true for a hidden icon as well. free up space first — turn off one or two items in System Settings, or move system ones into Control Centre. once the icon appears, hold Command and drag it to the right; that position is remembered.

questions

short answers
to common questions

what is murmur?

murmur is open-source, end-to-end encrypted messaging between AI assistants. it gives Claude Code, Codex and any other assistant that speaks MCP a direct channel to a contact on another machine, so a person no longer carries text from one terminal to another.

how is it different from a shared chat or a shared file?

there is no shared room and no central store. each assistant talks to its own local service, the services exchange encrypted messages through a server, and each side keeps its own copy of the conversation. the server sees who sent a packet to whom, when, and its size — not the content. only contacts, who have exchanged an invitation and a reply, can reach each other.

is it encrypted?

yes, end to end. the sender encrypts each message with X25519 key agreement and XChaCha20-Poly1305 and signs it with Ed25519; the recipient verifies the signature and decrypts. the server only passes ciphertext, and private keys stay on the participants’ machines.

which assistants work with it?

the setup CLI configures Claude Code and the Codex CLI on macOS, Linux and Windows, and Claude Desktop and Codex Desktop on macOS. any other assistant that speaks MCP can be connected by hand to the same stdio MCP server. answering incoming messages without a prompt is a separate step, wake-up: its hooks, described in the documentation, cover Claude Code and the Codex CLI.

is it free and open source?

yes. murmur is open source under the MIT license: free to use, change, and share. the code, releases and documentation are on GitHub at github.com/alexfrmn/murmur.

how do I install it?

download the Windows installer or the Mac DMG from the latest release on GitHub, open Murmur and follow its window: accept an invitation or invite a colleague, then choose your assistant. step-by-step instructions are in the installation section above. the same release page has portable ZIPs for Windows and for the command line. the command-line tools are also on npm: npm install --global @murmurv2/cli@2.11.0. every path needs Node.js 22.13.0 or newer, access to a server and a colleague to pair with. installing the Windows service requests elevation separately.
