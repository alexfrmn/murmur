# site/

Страница murmur, домен `https://murmurconnect.com/`. Статика: `index.html`, шрифт,
иконки, картинка для превью ссылок и файлы для поисковиков и ИИ-поиска (раздел
«SEO/GEO» ниже). Сборки нет, деплой — копирование каталога.

```
node scripts/build-site-ru.mjs   # после любой правки index.html: пересобрать ru/index.html
python3 -m http.server 8732      # локально: / — английская страница, /ru/ — русская
```

## Решения, которые стоит знать до правок

**Страница делится зонами, а не рамками.** Тёмный первый экран, светлая зона про
устройство, тёмная про установку, тёмная стая, светлый подвал. Разделение фоном и
воздухом; рамок вокруг секций нет.

**Установка — для человека, промпт для помощника — второй путь.** Кнопка «начать»
ведёт в раздел `#install`: «установка на Mac» и «установка на Windows» пошагово, со
скриншотом каждого экрана и каждого предупреждения системы. За ним «первые пять минут»:
пригласить → коллега принимает → вставить ответ → проверить связь → первый живой вопрос.
Слова берутся из словаря продукта (`contracts/vocabulary.md`), и раздел «как это
устроено — пять слов» объясняет их на той же странице. Промпт с кнопкой «скопировать»
остался ниже, в разделе «установка из терминала», для тех, кто работает в терминале;
английский промпт по смыслу совпадает с русским, команды и флаги в нём не переводятся.

**Скриншоты стоят только настоящие.** Место каждого отмечено комментарием
`<!-- screenshot: <id> -->` ровно там, где встанет `<img>`: внутри шага, после его
текста. Макетов, рисунков и заглушек на месте скриншотов нет намеренно — картинки
приходят отдельным коммитом из сборок кандидата. Стиль `.steps img` уже задан.
Относительный `src` генератор сам поправит для `/ru/`, а `alt` переведёт по ключу
словаря в `data-i18n-alt` — так же, как `aria-label` и `title`.

**У каждого языка свой адрес: `/` — английский, `/ru/` — русский.** Раньше русский
включался скриптом, и краулер без JavaScript (Яндекс, большинство ИИ-краулеров) по
`?lang=ru` получал `<html lang="en">` и английский title. Теперь `site/ru/index.html` —
готовая русская страница: `lang="ru"`, русские title, description, Open Graph, Twitter,
canonical `https://murmurconnect.com/ru/`, JSON-LD и весь текст уже в разметке.

Её пишет `scripts/build-site-ru.mjs` из `site/index.html` и словаря `I18N.ru` в нём же.
Руками `ru/index.html` не правят: меняют `index.html` (статическую английскую разметку
и оба словаря), затем запускают генератор и коммитят оба файла — деплой копирует `site/`
как есть, сборки там нет. `tests/site-ru.test.mjs` падает, если закоммиченная русская
страница отличается от того, что рендерит генератор, и если статический английский
текст разошёлся с `I18N.en`: английская страница — это тот же рендер для `en`.
`node scripts/build-site-ru.mjs --check` делает первую проверку без тестов.

Генератор меняет текст каждого элемента с `data-i18n`, атрибуты по `data-i18n-aria`,
`data-i18n-title` и `data-i18n-alt`, метаданные, промпт, ссылку-переключатель и JSON-LD,
а относительные адреса (`fonts.css`, иконки, будущие скриншоты) поднимает на уровень
вверх: `../`. Элемент с `data-i18n` — лист: внутри только текст. Нужна ссылка или `<code>` посреди
фразы — фраза делится на соседние элементы, как `manualPrefix` и `manualLink`.
Английский промпт живёт в `<pre id="prompt">` с экранированными `&lt;` и `&gt;`, русский —
строкой `I18N.ru.prompt`; генератор экранирует его сам.

**Переключатель языка — обычная ссылка.** На `/` кнопка RU ведёт на `ru/`, на `/ru/`
кнопка EN ведёт на `../`: работает без JavaScript. Клик дополнительно запоминает выбор
в `localStorage` под ключом `murmur-language`. Первый визит всегда открывается по адресу,
независимо от языка браузера. Маленький скрипт в `<head>` делает две вещи:
- `?lang=ru` или `?lang=en` (старый адрес русской версии, на него могли остаться ссылки)
  отправляет на страницу этого языка через `location.replace` и запоминается как клик;
- на `/` запомненный русский выбор открывает `/ru/`. Только на `/`: этот адрес ещё и
  `x-default`, он не называет язык, поэтому решает выбор посетителя. `/ru/` никуда не
  уводит: адрес, в котором язык назван явно, всегда показывает этот язык.

Без `localStorage` (приватный режим, запрет сайта) редиректов нет — язык решает адрес.

**Предупреждения неподписанных сборок ограничены проверенными путями.** Блок перед
установкой называет конкретные ОС, браузер и артефакт, отделяет наблюдавшийся текст
диалога от перевода и не выдаёт само предупреждение за проверку безопасности. Для
релиза v2.11 блок называет четыре точных артефакта, требование внешнего Node.js 22.13.0+ и
ведёт на одну страницу релиза. Автоматические архивы GitHub Source code явно отделены
от готового runtime; загрузка, замена поставки и повторный запуск остаются ручными.
Для существующей службы Windows страница ведёт на отдельную инструкцию: старая CLI
сначала удаляет регистрацию службы с её старым runtime path, профиль сохраняется,
а `init` и `join` не запускаются повторно. Затем каждый ранее настроенный MCP-клиент
перепривязывается новым CLI с `--replace` и перезагружается. Старый комплект сохраняют
до вернувшегося сообщения. Ссылка ведёт на поддерживаемую инструкцию в `main`:
в неизменённом опубликованном ZIP 2.10.0 этот шаг ещё пропущен.

**Анимация — чистая функция фазы.** Шесть секунд, замкнутый цикл, детерминированный LCG,
никакого накопления состояния: тот же приём, что в канальных плашках AI Mindset. Отсюда
же эстетика — поле `#070707`, JetBrains Mono строчными, 1px рамка с угловыми метками,
красный `#D92027` **одной дозой** на всю страницу.

Красная доза здесь — пакет, который едет по ребру между двумя агентами. Смысл прямой:
то, что едет, зашифровано.

**Кнопки** повторяют механику лендинга Михаила: плашка под низом, при наведении кнопка
уезжает влево-вверх, а плашка вырастает. Красная — основная, обведённая — вторая.

**Стая живёт движением, а не миганием.** Граф стоит постоянно; по рёбрам едут пакеты,
подсвечивая ребро, по которому идут, и вспыхивая в узле, до которого доехали. Вокруг
надписи вырезана дыра: ни точек, ни рёбер поверх текста, проверено по пикселям канвы.

**Образ: сегодня двое, стая — горизонт.** Murmuration стоит в конце страницы, а не в
начале. Стая на первом экране была бы обещанием, которого продукт не выполняет.

**`prefers-reduced-motion`** отключает движение и рисует один осмысленный кадр.

## Три гаммы и переключатель

По умолчанию — сумерки. `data-theme="dusk"` и `aria-pressed="true"` у кнопки сумерек
стоят прямо в разметке, поэтому до запуска скрипта не мелькает светлая гамма; скрипт
падает на `dusk` при пустом или незнакомом значении. Сохранённый выбор посетителя
(`murmur-theme` в `localStorage`) по-прежнему главнее. `theme-color` для панели браузера
берётся из поля текущей гаммы.

Кнопки в шапке меняют гамму без перезагрузки, выбор запоминается. Цвета рисунков —
графа, схемы и дыма — берутся из тех же переменных, что и вёрстка: иначе при смене
гаммы менялся бы текст, а картинки оставались от прошлой.

| гамма | поле | акцент | текст к фону | акцент к фону | текст на акценте |
|---|---|---|---|---|---|
| песок | `#f7f3ea` | `#b5480d` | 13.7 | 4.9 | 5.4 |
| сумерки | `#141824` | `#f0a868` | 14.7 | 8.9 | 9.1 |
| мята | `#f0f6f3` | `#0f766e` | 12.9 | 5.0 | 5.5 |

Числа — отношение контраста по WCAG, измерено на странице, а не прикинуто. Норма для
обычного текста 4.5; все три гаммы её проходят с запасом. Акцент песка сначала давал
4.26 и был затемнён до `#b5480d` именно по замеру.

Каждая гамма собрана по одному правилу: нейтральное поле, текст из той же тёплой или
холодной семьи, один акцент и один приглушённый тон для графики. Второго акцента нет
нигде — иначе страница начинает спорить сама с собой.

## Форма

Скругления заведены тремя токенами: 22 пикселя у зон, 14 у карточек и блока промпта,
10 у кнопок. Прямых углов на странице не осталось — прежняя версия читалась как схема
именно из-за них.

## Дым на всю страницу

Фон страницы — поле направлений: сотни коротких следов идут по медленно меняющемуся
полю, а кадр за кадром поверх ложится полупрозрачная тёмная вуаль, поэтому след не
стирается сразу, а расплывается. Курсор подмешивает вихрь вокруг себя.

Образец — эффект «烟雾流动» из [MotionVault](https://xiyu519.github.io/MotionVault/particles)
(репозиторий под MIT). Код здесь свой: библиотека даёт React и TypeScript, а странице
нужна была одна функция без сборки и зависимостей.

Два числа подобраны, а не взяты с потолка, и их стоит знать перед правкой. **Скорость
110 пикселей в секунду:** при меньшей отрезок за кадр короче пикселя, след не
набирается и гаснет под вуалью быстрее, чем накопится, — первая версия была именно
такой и выглядела пустым экраном. **Вуаль 3%:** след живёт около трёх секунд; гуще —
превращается в мельтешение, реже — поле зарастает.

Плотность считается от площади окна: на телефоне следов меньше, а не мельче.

**Первый экран из дыма исключён.** Секция непрозрачна и перекрывает холст: там уже живёт
граф двух агентов, и двух подвижных слоёв на одном экране быть не должно. Дым виден на
остальных тёмных участках — установка и полоса про стаю прозрачны.

## Статика ссылается на себя с версией

`fonts.css?v=20260923-1`, а также `favicon.svg`, `apple-touch-icon.png`,
`site.webmanifest` и `og.png` с тем же суффиксом. Версия в адресе означает, что любое
обновление меняет адрес, и кеш перестаёт быть отдельной сущностью, о которой нужно
помнить. Стенд уже поймал обратное: посредник закешировал 404 по адресу без версии и
держал его после того, как файл появился.

При правке файла версию нужно поднимать. Исключения — адреса, которые фиксирует
соглашение, а не мы: `robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`.

## Чего на странице нет намеренно

- автоматического выбора или установки артефакта: ссылка ведёт на страницу релиза,
  где человек выбирает точный неподписанный файл для своей платформы;
- версии 2.12 в тексте: разделы установки ведут на `releases/latest` и называют файл по
  окончанию (`.dmg`, `setup.exe`), а команда npm стоит с версией, которая реально
  опубликована (`@murmurv2/cli@2.11.0`, в npm с 24.09.2026);
- обещания «три команды»: честный счёт — пять шагов и два человека;
- витрины дефектов: решение владельца страницы. Честность держится отсутствием
  обещаний. Виндовые грабли стоят по месту, внутри шагов установки, где человек на них
  наступает.

## Что осталось техническим долгом

`fonts.css` — JetBrains Mono в base64, 250 КБ. Первую отрисовку он больше не держит:
стили подключены как `media="print"` с переключением на `all` по `onload` (плюс
`preload` и `<noscript>`), в `@font-face` стоит `font-display: swap`. Текст рисуется
сразу системным моноширинным и меняется на JetBrains Mono, когда файл пришёл.
Правильное решение прежнее — обычные `woff2` файлами вместо base64.

## SEO/GEO

Цель — чтобы страницу находили по запросам вроде «AI agent messaging», «agent to agent
communication», «MCP agent messaging», «Claude Code Codex talk to each other» в Google,
Bing, Яндексе и чтобы на неё ссылались ИИ-поисковики (ChatGPT search, Perplexity,
Claude, Exa).

**Канонический домен — `murmurconnect.com`.** Он прописан в canonical, `hreflang`,
Open Graph, структурированных данных, `robots.txt`, `sitemap.xml` и `llms*.txt`. При смене
домена менять во всех этих местах сразу.

| файл | зачем |
|---|---|
| `index.html` `<head>` | title и description с ключевыми фразами, canonical, `hreflang` en/ru/x-default, Open Graph и Twitter card, иконки, manifest |
| `index.html` JSON-LD | `WebSite` и `SoftwareApplication` (версия, лицензия MIT, репозиторий, загрузка) плюс отдельный блок `FAQPage` с `id="faq-ld"` |
| `index.html` `#faq` | видимые вопросы и ответы, на английском в разметке и на русском в словаре |
| `og.png` | превью ссылки 1200×630 в гамме сумерек |
| `favicon.svg`, `apple-touch-icon.png` (180×180), `icon-512.png`, `site.webmanifest` | иконки; рисунок тот же, что был в inline-иконке |
| `robots.txt` | разрешает всё и явно называет поисковых, ИИ-поисковых и обучающих краулеров; ссылка на sitemap |
| `ru/index.html` | русская страница, сгенерирована `scripts/build-site-ru.mjs`; руками не править |
| `sitemap.xml` | `/` и `/ru/` с `xhtml:link` на обе версии |
| `llms.txt` | индекс по соглашению llmstxt.org: H1, цитата-резюме, разделы ссылок |
| `llms-full.txt` | самодостаточный текст о murmur для языковых моделей |

**Схема FAQ повторяет видимый FAQ дословно.** Добавили, убрали или переписали вопрос —
правка идёт в карточку `#faq` и ключи `faqNq`/`faqNa` обоих словарей; блок `faq-ld`
на обеих страницах пересобирает генератор (для английской — запуском на `en` и записью
результата в `index.html`; тест скажет, если блок разошёлся со словарём). Схема без
видимого текста — нарушение правил Google для структурированных данных. Описания и
`featureList` русского JSON-LD лежат в `I18N.ru` (`ldSiteDescription`, `ldAppDescription`,
`ldRequirements`, `ldFeatures`); английский блок в разметке — их источник.

`keywords` в JSON-LD — поисковые слова, а не текст страницы: там остаются
«agent-to-agent» и «NATS», по которым ищут. Линтер словаря читает JSON-LD, поэтому каждое
такое слово стоит отдельным исключением в `contracts/vocabulary-allowlist.json`.

**Факты в `llms*.txt`, FAQ и JSON-LD берутся только из репозитория** — README,
SECURITY.md, CHANGELOG.md, `docs/`. `@murmurv2/cli@2.11.0` опубликован в npm 24.09.2026;
старые пакеты реестра не рекомендуются. Версию (`softwareVersion`, команда npm, тексты
про релиз) поднимать вместе с остальной страницей.

**Команды с npm-скоупом обёрнуты в `<!--email_off-->…<!--/email_off-->`.** Cloudflare
Email Obfuscation принимает `@murmurv2/cli@2.11.0` за адрес почты и подменяет его на
`[email protected]` — так уже было на живом сайте, пока Alex не выключил обфускацию
24.09. Обёртка защищает видимый текст, если её включат снова: `<code>` с командой,
`<pre id="prompt">` и ответ FAQ про установку. `<head>` и `<script>` Cloudflare не
трогает, поэтому JSON-LD и словарь остаются без обёртки (комментарий внутри JSON и
не допустим). Тест проверяет, что вне этих обёрток в видимом тексте нет `@scope/…`.

**Перед деплоем за Cloudflare** проверить, что его блокировка ИИ-ботов и управляемый
`robots.txt` не перекрывают этот файл: иначе явные `Allow` здесь ничего не дают.
