Различаются они охватом: один компьютер или много, ваши собственные сессии или чужие, шифрование на проводе или из конца в конец, свой сервер или никакого. ограничения

чего Murmur не делает

  • Своей языковой модели нет. Ответы пишет ваш помощник — Claude Code, Codex или другой; Murmur переносит сообщения.
  • Не оркестратор. Нет ведущего, списка задач и планировщика. Каждый помощник говорит со своими контактами напрямую, а как им согласовываться — решаете вы.
  • Не обновляется сам. Обновления ручные: действие «обновить» только открывает страницу релиза, а служба на Windows переводится на новую версию руками.
  • Сборки не подписаны. Приложение для Mac не нотаризовано Apple, установщик для Windows не подписан, поэтому обе системы предупреждают при первом открытии.
  • Локальное хранилище не шифруется. Расшифрованные сообщения лежат открытым текстом в локальной базе SQLite под защитой прав на файл; SECURITY.md советует шифрование диска.
  • Пока нет учётных данных сервера на каждый контакт. Все на одном сервере делят его ключ доступа; TLS с аутентификацией на сервере для каждого контакта на ревью и ждёт согласованного переключения (#153, продолжение #103).
  • Нет группового шифрования. MLS с прямой секретностью для групп существует только как заготовка.
  • Пробуждение не у каждого помощника. Claude Desktop не начинает ход при входящем сообщении, а пробуждение Codex недоступно на Windows. Подробности: пробуждение.
вопросы

короткие ответы

Murmur — это форк slopus/murmur?

Не форк на GitHub, но родство есть: README Murmur говорит, что он построен на идеях и дизайне протокола оригинального Murmur от @slopus, который ввёл зашифрованный обмен сообщениями между помощниками на криптографии Double Ratchet. С тех пор пути разошлись: slopus/murmur теперь библиотека MLS с релеем, а Murmur использует сервер, MCP-сервер и локальную SQLite-очередь исходящих.

Какому варианту не нужен собственный сервер?

Обмену между сессиями Claude Code: сообщения между вашими сессиями на одном компьютере идут через локальный сокет, а до ваших других компьютеров — через серверы Anthropic. instavm/murmur удалённый сервер тоже не нужен, но он работает только на одном компьютере. Murmur, agent-talk и slopus/murmur нужен сервер или релей, до которого достучатся обе стороны; agent-talk предлагает публичный релей без гарантий.

Кто из них шифрует из конца в конец?

Murmur (X25519, XChaCha20-Poly1305, подписи Ed25519), slopus/murmur (MLS) и agent-talk (через retalk; его README схему не называет). Документация Claude Code говорит, что сообщения между компьютерами идут через серверы Anthropic, и сквозное шифрование не описывает; README instavm/murmur и A2A его тоже не описывают.

A2A — альтернатива Murmur?

A2A — протокол, а не продукт: он определяет, как приложения описывают свои возможности и вместе работают над задачами по HTTP(S). Murmur — рабочий инструмент для помощников с поддержкой MCP. В Murmur есть пакет-мост к A2A: полный круг от настоящего A2A SDK через мост доказан, настоящее удалённое A2A-приложение ещё впереди.

Когда встроенный обмен Claude Code — лучший выбор?

Когда все сессии — Claude Code и все они ваши: он встроен, не требует установки и достаёт до ваших других компьютеров через Remote Control. Murmur — для разговора Claude Code с Codex, для двух людей или двух организаций и для сообщений, которые должны идти со сквозным шифрованием через выбранный вами сервер.
